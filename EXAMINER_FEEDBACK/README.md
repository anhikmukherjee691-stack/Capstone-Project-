# Examiner Feedback and Improvement Plan

## Project: ANOVYX AI
### AI-Driven Intelligent Fraud & Anomaly Detection System

This document records the feedback received during Review 1 and Review 2 and the corresponding improvement plan.

## Review 1 – Examiner Feedback

### 1. Proper Literature Review
**Feedback:** Do a proper literature review.

**Action Taken / Planned:**
- Review research papers published between 2022 and 2026.
- Study existing fraud detection approaches.
- Compare the algorithms, datasets, evaluation metrics, and limitations.
- Identify the research gap relevant to ANOVYX AI.

### 2. Focus on Evaluation Metrics
**Feedback:** Evaluation matrix needs to be focused.

**Action Taken / Planned:**
- Include Accuracy, Precision, Recall, F1-score, ROC-AUC, and PR-AUC.
- Generate and analyse the confusion matrix.
- Focus on false positives and false negatives.
- Avoid relying on accuracy alone.

### 3. Understand Technical Terminology
**Feedback:** Know the meaning of keywords used in the presentation.

**Action Taken / Planned:**
- Document the important machine learning concepts.
- Explain class imbalance, anomaly detection, feature engineering, hyperparameters, and decision thresholds.
- Maintain clear explanations of the algorithms used.

### 4. Research Papers
**Feedback:** Search for papers published between 2022 and 2026.

**Action Taken / Planned:**
- Identify relevant research papers from the specified period.
- Record their datasets, algorithms, evaluation methods, results, and limitations.
- Use the findings to establish the project's research gap.

## Review 2 – Examiner Feedback

### 1. Lack of Clarity
**Feedback:** There is no clarity.

**Action Taken / Planned:**
- Clearly define the problem statement.
- Explain the proposed system architecture and methodology.
- Distinguish completed implementation from planned development.
- Explain how each algorithm contributes to fraud detection.

### 2. No Significant Work
**Feedback:** No significant work.

**Action Taken / Planned:**
- Improve the dataset used for experimentation.
- Implement and evaluate an anomaly detection approach.
- Conduct a comparative analysis of the baseline and proposed hybrid model.
- Document experimental results and observations.

### 3. Learn the Basics
**Feedback:** Learn the basics.

**Action Taken / Planned:**
- Study the working principles of the selected algorithms.
- Understand preprocessing, feature engineering, training, testing, and model evaluation.
- Prepare explanations of the parameters and metrics.

### 4. Focus on the Algorithm
**Feedback:** Focus on the algorithm.

**Action Taken / Planned:**
- Study Random Forest and Isolation Forest in detail.
- Explain supervised learning and unsupervised anomaly detection.
- Investigate a hybrid approach using both algorithms.
- Compare their individual and combined performance.

### 5. Dataset Is Not Appropriate
**Feedback:** Dataset is not appropriate.

**Action Taken / Planned:**
- Evaluate the existing synthetic transaction dataset.
- Integrate the PaySim financial transaction dataset.
- Analyse the dataset's class distribution and feature quality.
- Use a reproducible training and testing procedure.

### 6. Focus on Parameters
**Feedback:** Focus on the parameters.

**Action Taken / Planned:**
- Document important model hyperparameters.
- Perform parameter tuning using training and validation data.
- Record the selected parameter values.
- Compare model performance before and after tuning.

## Overall Improvement Objective

The main objective is to transform the initial fraud detection prototype into a more reliable and properly evaluated machine learning system.

All proposed improvements will be validated experimentally before being reported as completed.
